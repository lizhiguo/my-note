# 知识库使用指南

> 本知识库采用 **OKF v0.2 元数据规范** 与 **Karpathy LLM-Wiki 双层架构** 协同驱动。
> 面向人类记录低负担，面向 AI 编译高可读，实现技术资产的持续演化与复利。

---

## 一、双层心智模型与架构分工

| 层次 | 目录 | 权限与规则 | 承担角色 |
| :--- | :--- | :--- | :--- |
| **用户手写区** | `sources/` | **人类私有，只读不篡改** | 随手笔记、长文剪藏、日常思考。按个人习惯组织（如 `01 学习笔记`、`02 技术` 等），**免除一切 Frontmatter 约束**。 |
| **专属资源区** | `sources/09 资源/` | **人类私有，只读不改** | 集中收纳手写笔记的图片附件（`attachments/`）与笔记模板（`templates/`）。 |
| **Agent 编译区** | `wiki/` | **Agent 维护，动态演进** | 由 Agent 从 `sources/` 提炼出的原子概念卡片，严格执行 OKF Frontmatter 契约与高密度 `[[双链]]` 引用。 |
| **全局根文件** | `index.md` / `log.md` | **OKF 规范保留文件** | 记录知识库版本、全库概览与全局更新履历。不可作为普通概念页。 |

## 二、人类日常操作流（如何写笔记）

1. **手写无负担**：
   - 需要沉淀技术点或灵感时，直接点开你熟悉的 `sources/02 技术/...` 或 `sources/01 学习笔记/...` 直接写。
   - 文件如何命名、段落如何排版，完全由你说了算，不需要适配任何复杂的 Agent 规则。
2. **笔记颗粒度建议（兼顾书写轻松与编译质量）**：
   - **纯语言/语法技巧（合写归纳）**：同一门语言的小语法、避坑点合写在一篇（如 `sources/02 技术/后端/kotlin语法技巧.md`），内部用二级标题分隔。
   - **框架整合与工程实战（单独成文）**：涉及具体框架或架构模式的笔记，单独开一篇（如 `sources/02 技术/后端/SpringBoot配置类使用-Kotlin实践.md`）。
   - **第三方库与工具包（清单式归纳）**：同领域的依赖库集中记录（如 `sources/02 技术/后端/Kotlin好用库.md`），列出库名、用途与简短调用代码。
   - **独立工具与平台**：放入 `sources/04 工具/`（如命令行工具、抓包软件、调试 API）。
   - **随手灵感与未分类碎片**：放入 `sources/06 随手记/`。
3. **网页剪藏暂存**：
   - 外部剪藏插件建议默认保存至外层临时收件箱（如 `Clippings/`）。经过挑选后，再移入 `sources/` 对应分类触发编译。
4. **附件与模板**：
   - 截图与文件附件自动存入 `sources/09 资源/attachments/`。
   - 笔记模板存放于 `sources/09 资源/templates/`。

## 三、Agent 协作流（常用指令与规则）

平时与 Agent（AI 助手）协作时，主要通过以下三种模式交互：

### 1. 资料摄入（Ingest）
* **指令示例**：
  > “我刚才在 `sources/02 技术/后端/` 下写了 `Kotlin协程实践.md`，请帮我 Ingest 摄入到知识库中。”
* **Agent 遵循规范**：
  - **先汇报再动笔**：预报抽取概念、受影响页面与潜在逻辑矛盾；
  - **动态创建分类**：按需在 `wiki/` 下动态建立对应分类目录（如 `wiki/01-Kotlin语言/`），初始状态不预建空文件夹；
  - **严禁静默覆盖**：当新笔记与现有结论冲突时，显式添加 `> ⚠️ 矛盾说明` 提示框；
  - **自动更新索引与日志**：生成条目后，自动刷新 `wiki/索引.md`，并在 `wiki/操作日志.md` 中追加流水。

### 2. 知识库查询（Query）
* **指令示例**：
  > “根据本知识库，我们在项目中关于全局状态管理和数据获取的最佳实践是什么？”
* **Agent 遵循规范**：
  - 以 `wiki/索引.md` 为唯一入口进行检索定位；
  - 回答时采用行内双链标注出处 `(→ [[页面名]])`。

### 3. 一致性体检（Lint）
* **指令示例**：
  > “请执行一次知识库 lint 体检，列出所有的断链、孤儿页与未登记条目。”
* **终端独立执行**：
  ```bash
  # <skill_dir> 即 okf-wiki skill 所在根目录
  python "<skill_dir>/scripts/okf_lint.py" "当前知识库绝对路径"
  ```
  本机实际路径：`python "C:/Users/king/.codebuddy/skills/okf-wiki/scripts/okf_lint.py" "D:/mywork/mydoc/obsidian-knowledge/my-note"`

## 四、OKF v0.2 Frontmatter 核心契约速查

`wiki/` 下的编译产物必须包含以下元数据：

```yaml
---
type: Concept                            # 必填。常见值：Concept | Hub | Tech Design | ADR | Project
title: 展示名称                           # 缺省从文件名推导
description: 一句话摘要，供索引检索展示     # 推荐填写
tags: [architecture, backend]           # 跨维度标签
status: stable                          # draft | stable | deprecated
generated:
  by: workbuddy/gpt-5                   # Agent 标识
  at: 2026-10-10T10:00:00+08:00         # 必须带明确时区偏移量的 ISO 8601
verified:
  by: human:laoli                       # 人工确认者标识
  at: 2026-10-10T10:00:00+08:00         # 确认时间
sources:
  - id: kotlin-ref                      # 稳定锚点 ID，正文用 [^kotlin-ref] 引用
    resource: /sources/02 技术/后端/Kotlin笔记.md  # 统一使用以 / 开头的 Bundle 根绝对路径
    title: Kotlin 笔记
---
```

## 五、十大铁律

1. **`sources/` 只读**：Agent 永远不得直接覆写或修改原始手写资料。
2. **矛盾显式标注**：遇到结论分歧显式标注并询问人类，绝不静默覆盖。
3. **索引先行**：所有查询必须始于 `wiki/索引.md`，所有摄入必须终结于更新该索引。
4. **OKF 强约束**：`wiki/` 内非保留名的 `.md` 必须具备非空 `type`。
5. **时间戳必带时区**：严格遵循 ISO 8601 规范（如 `+08:00` 或 `Z`）。
6. **Actor 前缀规范**：人工确认为 `human:<id>`，Agent 生成为 `<producer>/<version>`。
7. **双链使用扁平化**：跨页面互相引用统一使用 `[[页面名]]`，避免 Obsidian 移动文件后路径失效。
8. **批量改动先确认**：Lint 脚本只负责出具报告，动手修复前必须经由人类批准。
9. **好答案入库沉淀**：与 Agent 的深度讨论和高质量结论，必须落盘为 Wiki 词条。
10. **改动即时落盘**：编译与调整直接在本地文件系统完成，并在 `wiki/操作日志.md` 留下痕迹。
